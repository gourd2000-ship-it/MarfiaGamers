# 재입장 기능 구현 계획

## 목표

새로고침이나 일시적인 네트워크 끊김 뒤에도 같은 브라우저의 참가자가 역할, 생존 상태, 제출한 행동을 유지한 채 같은 방으로 복귀한다. 명시적인 `게임 나가기`는 즉시 퇴장으로 유지한다.

## 설계 결정

- 브라우저별 난수 재입장 토큰을 `localStorage`에 보관하고, 서버에는 토큰의 안전한 해시만 보관한다.
- 연결 종료는 즉시 기권으로 처리하지 않고 60초 유예 상태로 둔다. 유예가 끝난 뒤에만 기존 기권 처리를 적용한다.
- 새 Socket ID를 기존 참가자에 연결하고, 개인 역할과 공개 게임 상태를 다시 전송한다.

## 작업 순서

### Task R1: 재입장 토큰 계약과 참가자 식별

**수용 기준**

- [ ] 방 생성·입장 성공 시 재입장 토큰을 한 번만 발급한다.
- [ ] 토큰이 없는 요청은 기존의 새 참가자로 처리한다.
- [ ] 토큰 값 자체는 다른 참가자나 공개 상태에 노출하지 않는다.

**검증:** 계약·세션 단위 테스트, `npm.cmd test -- tests/room-session.test.ts tests/realtime-server.test.ts`.

### Task R2: 연결 종료 유예와 서버 재연결

**수용 기준**

- [ ] 연결 종료 뒤 60초 안에 유효 토큰으로 접속하면 동일 참가자로 복원된다.
- [ ] 60초가 지나면 기존처럼 기권 처리되고 이후 재입장은 거부된다.
- [ ] 명시적 게임 나가기는 유예 없이 즉시 기권 처리된다.

**검증:** 가짜 스케줄러를 이용한 Socket 통합 테스트.

### Task R3: 브라우저 자동 복원과 상태 동기화

**수용 기준**

- [ ] 새로고침 후 방 코드와 재입장 토큰으로 자동 복귀를 시도한다.
- [ ] 복귀 성공 시 역할, 진행 페이즈, 남은 시간, 개인 조사 결과가 정상 표시된다.
- [ ] 복귀 실패 시 이유를 알리고 새 방 코드 입장 화면을 표시한다.

**검증:** React 테스트 및 새로고침을 모사한 Playwright 흐름.

### Checkpoint

- [ ] 전체 테스트와 프로덕션 빌드가 통과한다.
- [ ] 실제 두 브라우저에서 새로고침, 일시적 네트워크 단절, 명시적 나가기를 각각 확인한다.

## 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 토큰 탈취로 인한 참가자 탈취 | 긴 난수 토큰, 서버 해시 저장, HTTPS 전용 운영 |
| 유예 중 게임이 멈춤 | 유예 참가자는 행동 대기 대상에서 제외하고 유예 만료 시만 기권 처리 |
| 이전 Socket 타이머의 중복 실행 | 방 revision 검증을 모든 유예·재입장 콜백에 적용 |
