# 게임 중 방 번호 및 60초 재접속 계획

## Overview

게임 보드의 방 요약에서 여섯 자리 방 번호를 보여 주고, 참가자별 비공개 재접속 토큰으로 60초 내 동일 역할을 복원한다. Socket.IO 연결 상태 복구는 같은 탭의 일시 단절을 돕고, 페이지 재진입은 애플리케이션 토큰으로 인증한다.

## Architecture Decisions

- 게임 엔진은 영구 참가자 ID를 유지하고, 현재 Socket ID는 별도로 바인딩한다.
- 토큰은 생성·입장 성공 응답으로 한 번만 전달하고 `sessionStorage`에 방별 보관한다.
- 예상치 못한 단절만 60초 유예한다. 명시적 나가기는 즉시 기권한다.
- 유예 중 게임 타이머는 계속 진행하며, 만료 때만 기존 기권 경로를 실행한다.

## Task List

- [x] Reconnect-1: 영구 참가자 ID·비공개 토큰·재접속 계약을 추가한다.
- [x] Reconnect-2: 방 저장소에 연결 바인딩과 60초 유예 상태 전환을 추가한다.
- [x] Reconnect-3: Socket.IO 복구·토큰 재접속·만료 기권 및 상태 재전송을 연결한다.
- [x] Reconnect-4: 게임 중 방 번호와 클라이언트 토큰 보관·재접속을 연결한다.

### Checkpoint

- [x] 유효 토큰은 역할을 복구하고, 불일치 토큰은 거부된다.
- [x] 전체 테스트, lint, 타입 검사, 빌드가 통과한다.

## Risks and Mitigations

| Risk | Mitigation |
| --- | --- |
| 방 번호로 역할 탈취 | 고엔트로피 비공개 토큰을 필수 검증한다. |
| Socket ID 변경으로 기록 손실 | 게임 엔진 키를 영구 참가자 ID로 분리한다. |
| 유예 타이머 경합 | 재접속 시 타이머를 취소하고 연결 ID를 재확인한다. |

# UI 개선 계획: 모바일 다크 게임 화면

## 목표

`doc/`의 네 장의 참고 이미지(역할 안내, 추방 결과, 투표, 참가자 현황)를 시각적 기준으로 삼아, 현재 기능을 유지한 채 모바일에서 한눈에 게임 상태와 다음 행동을 알 수 있는 UI로 정비한다. 서비스 문구는 현재처럼 한국어를 유지한다.

이번 UI 개선의 필수 사용자 경험은 다음과 같다.

1. 게임 중에는 현재 페이즈와 남은 시간을 화면 상단에서 항상 확인할 수 있다.
2. 내 역할은 평소 뒷면인 카드로만 보이고, 사용자가 카드를 터치할 때에만 앞면의 역할 정보를 확인한다.
3. 페이즈마다 해당 순간에 필요한 정보와 행동 하나만 중심 영역에 노출한다.

## 관찰과 범위

- 참고 이미지는 좁은 모바일 화면의 다크 테마, 고정 성격의 상단 진행 바, 한 개의 주 행동, 2열 참가자 카드로 일관된다.
- 현재 화면은 기능 컴포넌트가 모두 세로로 나열되고 공통 스타일시트가 없다. 게임 규칙·Socket 이벤트·권한 모델은 바꾸지 않는다.
- 참고 이미지의 `Day 1` 표시는 현재 공개 게임 상태에 일차 정보가 없으므로, 1차에서는 단계명으로 표시한다. 실제 일차가 꼭 필요할 때만 별도 계약 변경 작업으로 분리한다.

## 설계 결정

- 모바일 우선(기준 320px)으로 만들고, 넓은 화면에서는 중앙 게임 보드의 최대 폭만 확장한다.
- 색만으로 상태를 전달하지 않는다. 생존·탈락·선택·오류는 텍스트와 아이콘/배지도 함께 표시한다.
- 역할, 마피아 동료, 경찰 조사 결과처럼 개인 정보인 컴포넌트의 렌더링 조건은 유지한다.
- 테스트가 사용하는 기존 한국어 접근성 이름, `role`, 입력 `label`을 보존하거나 테스트와 함께 의도적으로 갱신한다.
- 게임 중 상단 바에는 단계명·카운트다운·연결 상태와 뒷면 상태의 `내 역할 확인` 카드만 둔다. 역할명은 카드 앞면을 열었을 때에만 DOM에 렌더링한다.
- 역할 카드는 로컬 UI 상태로만 뒤집는다. 서버가 새 역할을 전송하거나 방이 초기화되면 다시 뒷면으로 되돌린다. `prefers-reduced-motion`에서는 뒤집기 애니메이션을 생략한다.
- `phase` 값으로 중앙 작업 영역을 분기한다. 로비, 역할 확인, 각 밤 역할, 낮 결과, 투표/재투표, 게임 결과 외의 컴포넌트는 숨기며, 권한 없는 사용자는 행동 버튼 대신 짧은 대기 안내만 본다.

## 작업 순서

### Phase 1: 화면 토대

- [ ] Task UI-1: 디자인 토큰과 앱 셸을 만든다.
- [ ] Task UI-2: 방 만들기·입장·초대 로비를 카드형 흐름으로 정비한다.

### Checkpoint: 로비

- [ ] 320px 폭에서 가로 스크롤 없이 방 생성, 링크 복사/QR, 방 입장이 가능하다.
- [ ] 기존 로비 단위 테스트와 E2E 초대 흐름이 통과한다.

### Phase 2: 게임 진행

- [ ] Task UI-3: 단계·카운트다운·연결 상태를 상단 상태 바에 통합한다.
- [ ] Task UI-4: 터치로만 역할을 확인하는 뒤집힌 역할 카드를 만든다.
- [ ] Task UI-5: 페이즈별 중앙 작업 영역과 노출 규칙을 만든다.
- [ ] Task UI-6: 참가자 현황과 역할별 대상 선택을 공통 카드/그리드로 정비한다.

### Checkpoint: 플레이

- [ ] 낮 투표와 밤 역할 행동에서 가능한 대상, 선택 행동, 남은 시간이 명확히 구분된다.
- [ ] 페이즈와 권한에 관계없는 정보·버튼이 중앙 작업 영역에 노출되지 않는다.
- [ ] 역할별 비공개 정보가 다른 참가자에게 표시되지 않는 기존 테스트가 통과한다.

### Phase 3: 결과와 품질

- [ ] Task UI-7: 추방·투표 집계·승패·재경기 화면을 결과 패널로 정리한다.
- [ ] Task UI-8: 접근성·반응형 회귀 검증과 실제 기기 시각 점검을 완료한다.

## 위험과 대응

| 위험 | 영향 | 대응 |
| --- | --- | --- |
| 강한 다크 테마의 낮은 대비 | 읽기 어려움 | 텍스트/버튼 대비와 색 외 상태 표기를 테스트한다. |
| UI 리팩터링 중 E2E 선택자 변경 | 게임 흐름 회귀 | 접근성 이름을 보존하고 각 단계 후 E2E를 실행한다. |
| 화면 장식이 역할 정보를 노출 | 게임 공정성 훼손 | 개인 역할 컴포넌트의 현재 조건부 렌더링을 유지하고 수신자 테스트를 실행한다. |
| 참고 이미지의 일차 표시를 임의로 계산 | 참가자 간 불일치 | 1차에서는 표시하지 않고, 필요 시 서버 권한 상태로 별도 추가한다. |

## 결정이 필요한 후속 사항

- 상단의 실제 `Day N` 표기가 필요한가? 필요하다면 게임 엔진과 공개 Socket 상태에 서버 기준 일차를 추가한다.
- 아이콘은 외부 아이콘 패키지 대신 간단한 CSS/유니코드 표기를 쓸지, 별도 아이콘 세트를 도입할지 구현 전에 결정한다.

# 게임 제출·종료 흐름 보완 계획

## 목표

대상 선택은 클라이언트에서 먼저 확인한 뒤 `선택 완료`로 한 번만 서버에 제출한다. 서버는 현재 페이즈의 필수 행동 또는 투표가 모두 제출됐을 때만 다음 페이즈로 자동 전환한다. 게임 결과 뒤에는 참가자가 로비로 돌아가 새 게임을 시작하거나 방을 종료할 수 있다.

## 작업 순서

- [ ] Task Flow-1: 마피아 대상 제출 오류를 Socket 통합 테스트로 재현하고, 게임 상태와 방 상태의 수신 순서에 무관하게 유효한 마피아 제출을 처리한다.
- [ ] Task Flow-2: 밤 행동과 낮 투표의 선택/제출 UI를 분리하고, 서버가 필수 제출 완료 시 페이즈를 자동 진행하게 한다.
- [ ] Task Flow-3: 결과 화면에서 방장이 같은 참가자로 로비 복귀를 시작하고, 모든 참가자가 새 게임 또는 방 종료를 선택할 수 있게 한다.

## Checkpoint: 게임 흐름

- [ ] 마피아가 방장을 포함한 유효한 시민을 선택하고 `선택 완료`를 누르면 서버가 성공 응답을 준다.
- [ ] 모든 행동 권한자 또는 생존 투표자가 제출하면 방장 시간 넘기기 없이 정확히 한 단계만 진행한다.
- [ ] 결과 뒤 로비 복귀 또는 방 종료가 모든 참가자 화면에 일관되게 반영되고, 비밀 역할 정보는 초기화된다.

## Risks

- 자동 전환은 서버에서만 결정해 중복 제출·오래된 타이머·권한 없는 클라이언트가 상태를 진행시키지 못하게 한다.
- 로비 복귀는 기존 참가자의 연결을 보존하되, 이전 게임의 역할·행동·결과는 모두 삭제한다.
