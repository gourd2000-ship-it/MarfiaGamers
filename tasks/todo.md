# UI 개선: `doc/` 스크린샷 기반

## Task UI-1: 모바일 다크 디자인 토큰과 앱 셸

**설명:** 참고 이미지의 어두운 배경, 밝은 본문, 강조색, 둥근 카드와 버튼을 공통 CSS 토큰 및 중앙 게임 보드로 만든다.

**수용 기준:**
- [ ] 320px 이상 화면에서 앱 셸이 가로 스크롤 없이 표시된다.
- [ ] 기본·강조·위험 버튼, 카드, 입력, 상태 배지가 일관된 스타일을 사용한다.
- [ ] 키보드 포커스와 텍스트 대비가 다크 테마에서도 식별된다.

**검증:** `npm run lint`, `npm run test`, 320px/768px 수동 화면 점검.
**의존성:** 없음.
**예상 범위:** M.
**파일 예상:** `apps/web/src/main.tsx`, `apps/web/src/App.tsx`, `apps/web/src/styles.css`.

## Task UI-2: 로비·초대 흐름 카드화

**설명:** 방 만들기, URL 입장, QR 초대를 한 화면 흐름으로 정리하고, 방장에게는 참가자 수와 시작 가능 여부를 명확히 보여 준다.

**수용 기준:**
- [ ] 생성/입장 폼의 레이블과 오류 문구가 모바일에서 명확히 읽힌다.
- [ ] 초대 QR과 링크가 카드 안에 표시되고 링크 복사 동작을 제공한다.
- [ ] 게임 시작 불가 사유(2명 미만)가 버튼 근처에 표시된다.

**검증:** 로비 단위 테스트, `npx playwright test e2e/lobby-flow.spec.ts`.
**의존성:** UI-1.
**예상 범위:** M.
**파일 예상:** `apps/web/src/features/lobby/*.tsx`, `apps/web/src/App.tsx`, `tests/*room*`, `tests/invite-card.test.tsx`.

## Task UI-3: 상단 게임 상태 바

**설명:** 참고 이미지처럼 현재 단계, 남은 시간, 연결 상태를 상단에 모아 현재 해야 할 일을 먼저 보이게 한다. 실제 Day 번호는 서버 상태에 추가하기 전까지 노출하지 않는다.

**수용 기준:**
- [ ] 낮/밤/결과 단계와 남은 시간이 화면 상단에서 즉시 확인된다.
- [ ] 재연결·오류 상태가 게임 행동보다 눈에 잘 띄게 표시된다.
- [ ] 기존 `role="timer"`, 상태 안내와 단계 문구를 유지한다.

**검증:** 단계/카운트다운/연결 상태 단위 테스트와 다중 브라우저 수동 확인.
**의존성:** UI-1.
**예상 범위:** M.
**파일 예상:** `apps/web/src/App.tsx`, `apps/web/src/components/connection-status.tsx`, `apps/web/src/features/game/phase-*.tsx`, `tests/phase-*.test.tsx`.

## Task UI-4: 터치로 여는 뒤집힌 역할 카드

**설명:** 내 역할을 평소에는 뒷면 카드로 감추고, 사용자가 `내 역할 확인` 카드를 터치할 때만 앞면 역할을 표시한다. 역할 정보가 계속 화면에 남지 않게 한다.

**수용 기준:**
- [ ] 역할 수신 직후와 새 게임 시작 시 카드는 항상 뒷면에서 시작한다.
- [ ] 카드 터치/키보드 조작으로만 역할명과 역할 설명을 확인하고 다시 감출 수 있다.
- [ ] 감춘 상태에서는 실제 역할명이 화면과 접근성 트리에 노출되지 않으며, 모션 감소 설정을 존중한다.

**검증:** 역할 카드 컴포넌트 단위 테스트(기본 감춤·열기·다시 감춤·역할 변경 초기화)와 키보드 수동 점검.
**의존성:** UI-1, UI-3.
**예상 범위:** M.
**파일 예상:** `apps/web/src/features/game/role-card.tsx`, `apps/web/src/App.tsx`, `apps/web/src/styles.css`, `tests/role-card.test.tsx`.

## Task UI-5: 페이즈별 작업 영역과 노출 규칙

**설명:** 중앙 화면을 페이즈 전용 작업 영역으로 재구성한다. 현재 페이즈와 사용자 역할에 필요한 정보·버튼만 표시하고, 다른 행동은 렌더링하지 않는다.

**수용 기준:**
- [ ] 역할 확인은 역할 카드만, 밤은 해당 역할의 행동 또는 대기 안내만, 낮 안내는 결과만, 투표는 투표 대상만, 결과는 승패와 방장 제어만 중심에 표시한다.
- [ ] 로비의 초대·참가자·게임 시작 제어는 게임 시작 후 표시되지 않는다.
- [ ] 비권한 사용자에게는 역할 행동 버튼이 절대 표시되지 않는다.

**검증:** 페이즈별 렌더링 단위 테스트와 4인 Playwright 게임 흐름.
**의존성:** UI-3, UI-4.
**예상 범위:** M.
**파일 예상:** `apps/web/src/App.tsx`, 새 `apps/web/src/features/game/phase-workspace.tsx`, `tests/phase-workspace.test.tsx`, `e2e/lobby-flow.spec.ts`.

- [ ] 가능한 대상만 선택 가능하며, 선택 후 제출 상태가 명확하다.
- [ ] 마피아 동료/경찰 결과 등 개인 정보는 현재 사용자에게만 보인다.
